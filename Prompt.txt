# 5. GLOBAL CONFIGURATION

Create ONE centralized configuration system.

Create a clearly identifiable configuration file such as:

`config/site.config.ts`

or an equivalent structure.

All values that may reasonably change over time must be centralized.

Examples:

```ts
export const siteConfig = {
  name: "Carlos Caicedo",

  title: "AI · Data · Machine Learning",

  api: {
    baseUrl: "...",

    timeoutMs: 10000,

    retryAttempts: 2,

    retryDelayMs: 1000,

    cacheDurationMs: 60000
  },

  ai: {
    streamingEnabled: true,

    maxMessageLength: 4000,

    maxConversationMessages: 50
  },

  map: {
    defaultLatitude: 0,

    defaultLongitude: -75,

    defaultZoom: 3
  },

  features: {
    aiAssistant: true,

    nlpPlayground: true,

    databaseLab: true,

    knowledgeGraph: true,

    geospatial: true,

    resumeDownload: true
  }
}
```

The exact implementation may differ, but the principle is mandatory.

Create environment variables for values that should NOT be committed to source control.

Examples:

```text
NEXT_PUBLIC_API_BASE_URL
NEXT_PUBLIC_MAP_PROVIDER
NEXT_PUBLIC_ENABLE_AI
NEXT_PUBLIC_ENABLE_NLP
NEXT_PUBLIC_ENABLE_DATABASE_LAB
NEXT_PUBLIC_ENABLE_KNOWLEDGE_GRAPH
NEXT_PUBLIC_ENABLE_GEOSPATIAL
```

Do NOT expose secret API keys in frontend code.

Any future Groq API key must be handled server-side or through the backend.

The frontend must never contain a secret Groq API key.

# 21. ENDPOINT DOCUMENTATION

Create a file at the root of the project:

# `endpoints.txt`

This file is mandatory.

It must document EVERY REST request the frontend makes or expects.

For EVERY endpoint document:

* HTTP method
* URL/path
* purpose
* query parameters
* request body
* request headers if relevant
* success response
* response fields
* example JSON response
* expected HTTP status
* possible error responses
* frontend behavior when unavailable

Use a clear structure.

Example:

```text
==================================================
POST /api/ai/chat
==================================================

Purpose:
Send a user message to the AI assistant.

Request body:

{
  "message": "What AI projects has Carlos built?",
  "conversationId": "optional-id"
}

Success: HTTP 200

Response:

{
  "message": "...",
  "cards": [],
  "references": []
}

Streaming:
Optional.

Errors:

HTTP 408:
Request timeout.

HTTP 429:
Rate limit.

HTTP 500:
Backend error.

Frontend fallback:
Display an unavailable state and keep the rest
of the portfolio functional.
```

Document ALL endpoints.

Do not document endpoints that do not exist in the frontend.

Do not invent unnecessary endpoints.
